### P26-T1 — D71: the replay is one transaction over the union budget, and every superseded line is retired

- **"Nothing re-issued until the whole batch is admitted" — verified true, and there are two independent gates.** `replay_all` computes `rt_n` / `generic_n = len(pending) - rt_n` and raises one `PacingExceeded(max(realtime_wait_for_slots(rt_n), generic_wait_for_batch(generic_n)))` **before** any `_Entry` is touched (`ibkr/subscription_manager.py:171-176`). Then `generic_batch(generic_n)` re-checks and raises **from `__enter__`**, so the generator body never runs (`ibkr/pacing.py:139-146`): a `with`-statement whose `__enter__` raises never enters its body and never runs the `finally`, so a refused pass is not even stamped. The union arithmetic is exact because the only other path a reissue takes (`req_mkt_data`) is the generic gate, and RT reissues go through `RealtimeBarsManager.subscribe`, which uses `realtime_wait_seconds()`/`record_realtime_slot()` and **never** `throttle()` (`ibkr/realtime_bars.py:18-40`; grep confirms the only `throttle()` call sites are the four `market_data.py` request methods).
- **Unwind on a mid-batch raise — complete, and complete for the option legs specifically.** `except BaseException` retires each **newly issued** reqId through its own type's resolver, rebinds every pending entry to its old reqId (best-effort, logged), leaves `_entries` untouched, and re-raises (`:186-206`). I traced the option-leg case end to end because it is the one with mutable window state: `_option_reissue_leg` has already rewritten `_option_leg_req[leg]` to the new id and popped the old from `_option_req_ids`; the unwind's `rebind(old)` calls `_option_rebind_leg`, which pops the **new** id from `_option_req_ids`, restores `_option_leg_req[leg] = old`, and repoints the engine — and the old broker line is still live because retire only runs in phase 3. RT is symmetric (`_reissue_rt` never cancels; `_rebind_rt_req_id(old)` restores `_rt_req_id` + routing, so `on_realtime_bar`'s `req_id != self._rt_req_id` fence is consistent again). **No leaked pacing reservation:** `generic_batch`'s `finally` clears `_batch_remaining` on the exception path too, and `reset_for_tests` clears it as a backstop (`pacing.py:275-285`).
- **Per-type retirement — the option path that never cancelled now does.** `RT_BARS → _retire_rt_subscription` (`_unregister_req_id` + `rt_manager.unsubscribe`, `main_window.py:1118-1131`) and `OPTION_LEGS → _retire_option_subscription` (`_option_req_ids.pop` + `md_manager.cancel_mkt_data`, `:1133-1148`), installed once beside `self.sub_manager = SubscriptionManager()` (`:805-816`).
