NDThinkChart — Dead Code Review
===============================
Review date: 2026-10-27
Method: static reference/call-site inspection of the current workspace source.
No source files were changed; only this report was created. No tests were run.

Definition used
---------------
“Unreferenced” means no call/reference was found in first-party runtime source or
tests, after checking direct calls, attribute references, Qt/IBKR callback wiring,
and the JavaScript bridge. Static inspection cannot prove a symbol is unreachable
through reflection, a third-party plugin, or external code.

Authorship/native boundary: this report covers functions implemented in this
repository's first-party source. It excludes functions/methods supplied by
Lightweight Charts, Qt, IBKR's API, and other dependencies. The vendored
Lightweight Charts production bundle was not scanned. Custom project code under
`ui/lwc_*` and `chart_assets/lwc/` remains in scope; it is project code, not
native library code.

Summary
-------
I found a small set of strong dead-code candidates and some production-unused
helpers. The clearest dead chain is the market-data-line guard: its entry method
has no caller, so its count helper and imported assessor are also unreachable.
A few functions are deliberately described as parity references or public
helpers, but currently have no call sites or tests. Those should either be
removed or given a concrete consumer/test before they are treated as supported
interfaces.

Strong candidates: no caller found in runtime source or tests
------------------------------------------------------------

1. `MainWindow._ibkr_end_date` — `ui/main_window.py:168`
   No call sites. The backfill planner now owns formatting in
   `services/backfill_service.py:_format_end_date`; the only remaining mention
   of the old helper is documentation. It appears to be a stale pre-planner
   formatter. Removing it would also allow dropping `timezone` from
   `ui/main_window.py`'s datetime import (keep `datetime`, used elsewhere).

2. `BarCache.get_last_timestamp` — `data/bar_cache.py:75`
   No call sites in application code or tests. This API also omits `ext_hours`,
   unlike the mode-scoped cache methods, so it should not be revived without
   adding a mode argument and filtering the query.

3. `chart_model.plot_arrays` — `services/chart_model.py:111`
   No call sites in application code or tests. Its docstring refers to the old
   `ChartPanel._sync_plot_arrays` path; that caller is absent from the current
   project. The chart view now builds its data through other helpers.

4. `chart_model.volume_nice_family` — `services/chart_model.py:179`
   No call sites in application code or tests. It is separate from the active
   `nice_volume_max` helper and the live visible-volume ceiling calculation.
   The function looks like a leftover family generator.

5. `services.session_service._et_midnight` — `services/session_service.py:24`
   No call sites in application code or tests. The module uses `_ts_at_et`
   directly for session boundaries.

6. First-party JavaScript helpers `isFiniteOrNull` and `snapshotFor` —
   `chart_assets/lwc/primitives.js:93` and `chart_assets/lwc/chart.js:244`
   A repository-wide identifier scan found only the declaration for each name
   (no runtime or test references). They appear to be leftovers from earlier
   validation/state-snapshot code.

Dead call chain: no production entry point
-----------------------------------------

7. Market-data-line budget guard:
   - `MainWindow._guard_md_lines` — `ui/main_window.py:850`
   - `MainWindow._md_line_count` — `ui/main_window.py:840`
   - `md_assess` import — `ui/main_window.py:88`
   - `services.md_line_guard.assess` — `services/md_line_guard.py:20`

   `_guard_md_lines` has no caller in application source or tests. The count
   helper is called only by that method, and `md_assess` is called only inside
   that method. Consequently the assessment function and module have no active
   production path. The current `_md_line_count` only counts RT bars and
   watchlist rows. Project docs describe this as a retained guard for S0 ticks,
   but no runtime subscription path invokes it in the current source. If the
   guard is still required, connect it to the surviving subscription flow;
   otherwise remove the method, helper, import, and module together.

Production-unused or test-only API candidates
---------------------------------------------
These have tests, documentation, or explicit compatibility comments, so they
are not “unreferenced anywhere”; they are simply not used by the app's current
runtime path.

8. `services.drawing_service.next_group_seq` — `services/drawing_service.py:26`
   Referenced by its unit tests but not application code. Runtime group naming
   uses `DrawingStore.next_group_seq` (`data/drawing_store.py:43`), so there are
   two implementations of the same operation. Keep one shared implementation
   and have both runtime and tests use it, or delete the unused service helper.

9. `services.session_service.session_bands_for_range` —
   `services/session_service.py:89`
   Used by tests only. It is a small wrapper around `session_bands`; retain it
   if the explicit-range test seam is useful, otherwise tests can use the
   canonical function with lightweight bars.

10. `services.time_collapse_service.TimeCollapseMap.to_ts` —
    `services/time_collapse_service.py:126`
    The inverse mapping is part of the documented public API but has no call
    site in current source or tests. It may be intentional for future cursor or
    drawing conversion. Keep only if that use is planned; otherwise it and the
    reverse-map storage (`_display_to_ts`) are removable.

11. `services.sound_service.SoundService.is_enabled` —
    `services/sound_service.py:123`
    Getter has no call site; current consumers use `set_enabled` and
    `play_alarm`. Remove it unless it is an external API contract.

12. `ibkr.pacing.PacingManager.realtime_available_slots` —
    `ibkr/pacing.py:59`
    No call site in runtime or tests. Current callers use wait-based budget
    methods. It may be an abandoned polling/introspection API.

13. `ibkr.subscription_manager.SubscriptionManager.entries_of_type` —
    `ibkr/subscription_manager.py:86`
    No call site found. Likely diagnostic/introspection API; remove or expose it
    only if a real status view needs it.

14. `ibkr.subscription_manager.SubscriptionManager.has_subscription` —
    `ibkr/subscription_manager.py:79`
    No call site found. A source-removal regression test explicitly allowlists
    this method in its module, but does not invoke it. This is an intentional
    keep-list marker, not evidence of a live caller. Confirm whether the
    intended subscription query is still needed; otherwise remove the method
    and its allowlist exception.

15. `TickerSession.register_history_request` — `ui/ticker_session.py:734`
    This public wrapper only forwards to `_register_history_request`; no other
    caller was found. It is a compatibility wrapper candidate.

16. `MainWindow.primary_session` property — `ui/main_window.py:955`
    The property itself has no caller. Internal code uses `_primary_session`
    directly. Remove if no external/test consumer is planned; retain only if it
    is a deliberate public facade for plugins or future callers.

    No caller or test found. These appear to be inspection/debug accessors.

    removing it, since drawing edits are user-visible.

22. `LwcChartView.set_overlay` and `overlay_regions` — `ui/lwc_view.py:2670,

Framework and dependency-provided callback entry points were excluded from the
dead-code list when their registrations or overrides showed they are live.

Recommended cleanup order
-------------------------
1. Resolve the market-data-line guard chain: either reconnect it to a real
   subscription path or remove the dormant code, based on the current feature
   scope.
2. Remove clear stale helpers (`_ibkr_end_date`, `get_last_timestamp`,
   `plot_arrays`, `volume_nice_family`, `_et_midnight`) and their now-unused
   imports, after confirming no external consumers.
3. Decide whether the documented-but-unconsumed LWC and subscription APIs are
   real extension seams. For seams kept, add a direct contract test; otherwise
   delete the API and any matching docs/allowlist entries.

Scope and confidence
-------------------
Reviewed project-authored Python runtime source in main.py, config/, data/,
services/, ibkr/, ui/, packaging/, and custom JavaScript chart modules. Tests
were searched for references but not reviewed for test quality. Lightweight
Charts native/vendor code, other dependency/framework implementations,
generated files, and external consumers are outside this scan. A static
no-reference result is a strong cleanup signal, not a proof against reflection
or downstream imports.
